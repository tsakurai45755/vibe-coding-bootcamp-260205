# 日報アプリMVP 要件定義（EARS）

## 1. 概要
PCの作業画面スクリーンショット（画像1枚）から、所定テンプレートのMarkdown日報を自動生成する。
MVPは「1ページ完結（生成・編集・コピー・Markdownエクスポート）」とし、データベースは使用しない。

## 2. スコープ
### 2.1 MVPに含める
- 画像アップロード（ドラッグ&ドロップ / クリップボード貼り付け / ファイル選択）
- 画像1枚からの日報生成（Azure OpenAI GPT-4.1 利用）
- 生成結果（Markdown）の編集
- コピー機能
- Markdownファイルのエクスポート（ダウンロード）
- ローディング表示、ユーザー向けエラー表示
- バックエンドは FastAPI のWeb API

### 2.2 MVPに含めない（将来）
- 画像複数枚対応
- 生成履歴の表示/検索（DB含む永続化）
- ユーザーごとの認証・権限管理
- テンプレのカスタマイズUI
- モバイル最適化（最低限のレスポンシブは行うが、モバイル専用要件は対象外）

## 3. 用語
- **日報テンプレ**: 「作業内容」「進捗状況」「課題・問題点」の3セクション構成のMarkdown
- **セッション**: 同一ブラウザ利用者に対して払い出される識別（MVPはサーバメモリで一時保持のみ）

## 4. 前提・制約
- 技術スタック: React（フロント） + Python/FastAPI（バック） + Azure OpenAI GPT-4.1
- データベースは使用しない
- Azure OpenAI 認証は APIキーを環境変数で渡す（MVP）
- 対応ブラウザ: モダンブラウザ（IE11非対応）
- 画像データは永続保存しない

## 5. ユーザーストーリー（MVP）
- ユーザーとして、スクリーンショットを貼り付け/アップロードして、日報を自動生成したい
- ユーザーとして、生成された日報を少し編集してからコピー/保存したい
- ユーザーとして、失敗した場合に原因を理解して再試行したい

## 6. 受け入れ基準（EARS）

### 6.1 画像入力
- WHEN ユーザーが画像をドラッグ&ドロップしたとき、THE SYSTEM SHALL 画像を受理しプレビュー表示する
- WHEN ユーザーがクリップボードの画像を貼り付けたとき、THE SYSTEM SHALL 画像を受理しプレビュー表示する
- WHEN ユーザーがファイル選択で画像を選んだとき、THE SYSTEM SHALL 画像を受理しプレビュー表示する

- WHEN 受理したファイルが画像形式ではないとき、THE SYSTEM SHALL 生成処理を開始せずエラーメッセージを表示する
- WHEN 受理した画像がサイズ上限を超えるとき、THE SYSTEM SHALL 生成処理を開始せずエラーメッセージを表示する
- WHEN 受理した画像が読み取り不能（破損等）なとき、THE SYSTEM SHALL 生成処理を開始せずエラーメッセージを表示する

### 6.2 生成（フロント）
- WHEN ユーザーが「生成」操作を行ったとき、THE SYSTEM SHALL バックエンドへ画像を送信して生成を開始する
- WHILE 生成処理中、THE SYSTEM SHALL ローディング表示を行い、二重送信を抑止する
- WHEN 生成処理が成功したとき、THE SYSTEM SHALL 日報テンプレに従うMarkdownを表示する

### 6.3 編集・コピー・エクスポート
- WHEN 生成結果が表示されたとき、THE SYSTEM SHALL ユーザーがMarkdownテキストを編集できる
- WHEN ユーザーが「コピー」操作を行ったとき、THE SYSTEM SHALL 編集後のMarkdownをクリップボードへコピーする
- WHEN ユーザーが「エクスポート」操作を行ったとき、THE SYSTEM SHALL 編集後のMarkdownを`.md`ファイルとしてダウンロードさせる

- WHEN エクスポートファイル名が未指定のとき、THE SYSTEM SHALL 一意性を確保できるデフォルト名を付与する
  - 例: `daily-report-YYYYMMDD-HHmm.md`（実装で固定）

### 6.4 エラーハンドリング
- IF バックエンドが4xxを返したとき、THE SYSTEM SHALL ユーザーに入力起因のエラーとして表示し再試行方法を提示する
- IF バックエンドが5xxを返したとき、THE SYSTEM SHALL ユーザーにシステム起因のエラーとして表示し再試行を促す
- IF バックエンド通信がタイムアウトしたとき、THE SYSTEM SHALL タイムアウトとして表示し再試行を促す

### 6.5 バックエンド（生成API）
- WHEN バックエンドが画像生成リクエストを受信したとき、THE SYSTEM SHALL 画像形式/サイズ/内容を検証する
- WHEN 画像が検証に合格したとき、THE SYSTEM SHALL 必要に応じて前処理（リサイズ/圧縮）を行う
- WHEN モデル呼び出しに成功したとき、THE SYSTEM SHALL 3セクション構成のMarkdown日報を返す
- IF モデル呼び出しに失敗したとき、THE SYSTEM SHALL 再試行可能なエラーとして扱い、適切なエラー応答を返す

### 6.6 データ保持・削除
- THE SYSTEM SHALL 画像データを永続化しない
- THE SYSTEM SHALL 生成処理に必要な範囲でのみ画像データを一時保持し、処理完了後に速やかに破棄する
- THE SYSTEM SHALL セッションに紐づく一時データをサーバメモリに保持する場合、保持期間（TTL）を設定し期限到来後に削除する

### 6.7 セキュリティ・運用
- THE SYSTEM SHALL Azure OpenAI APIキーをコードに直書きしない
- THE SYSTEM SHALL APIキーを環境変数から読み込む
- THE SYSTEM SHALL CORSを設定し、フロントエンドのオリジンからのみアクセス可能にする（開発時）
- THE SYSTEM SHALL ログに機密情報（APIキー、画像の生データ）を出力しない

## 7. 非機能要件（MVP）
- 性能: 生成完了までの待ち時間は、ユーザーが「処理中」と理解できるUIを提供する（具体目標値はTBD）
- 可用性: ヘルスチェック用エンドポイントを提供する
- 保守性: 設定値（画像上限、タイムアウト、モデル名等）は環境変数または設定で変更可能とする
