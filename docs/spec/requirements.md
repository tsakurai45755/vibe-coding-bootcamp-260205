# 要件定義書（Requirements）

## 1. プロジェクト概要

### 1.1 目的
PC作業画面のスクリーンショット（画像1枚）から、所定テンプレート（3セクション構成）のMarkdown形式日報を自動生成するMVPアプリケーションを実装する。

### 1.2 スコープ
**MVPに含める機能:**
- 画像アップロード（ドラッグ&ドロップ / クリップボード貼り付け / ファイル選択）
- 画像1枚からの日報生成（Azure OpenAI GPT-4.1 利用）
- 生成結果（Markdown）の編集
- コピー機能（クリップボードへ）
- Markdownファイルのエクスポート（ダウンロード）
- ローディング表示
- ユーザー向けエラー表示
- FastAPI ベースのWeb API

**スコープ外（将来拡張）:**
- 画像複数枚対応
- 生成履歴の永続化（データベース使用）
- 認証・権限管理
- テンプレートカスタマイズUI
- モバイル専用最適化

### 1.3 技術スタック
- **フロントエンド:** React + TypeScript + Vite
- **バックエンド:** Python + FastAPI
- **AI:** Azure OpenAI (GPT-4.1 マルチモーダルモデル)
- **デプロイ:** Azure App Service (想定)
- **データベース:** 使用しない（セッションベースの一時保存のみ）

## 2. 機能要件（EARS形式）

### 2.1 画像入力

#### 2.1.1 画像アップロード - ドラッグ&ドロップ
**WHEN** ユーザーが画像をドラッグ&ドロップしたとき、**THE SYSTEM SHALL** 画像を受理しプレビュー表示する。

#### 2.1.2 画像アップロード - クリップボード貼り付け
**WHEN** ユーザーがクリップボードの画像を貼り付けたとき、**THE SYSTEM SHALL** 画像を受理しプレビュー表示する。

#### 2.1.3 画像アップロード - ファイル選択
**WHEN** ユーザーがファイル選択で画像を選んだとき、**THE SYSTEM SHALL** 画像を受理しプレビュー表示する。

#### 2.1.4 画像形式検証
**WHEN** 受理したファイルが画像形式ではないとき、**THE SYSTEM SHALL** 生成処理を開始せずエラーメッセージを表示する。

**サポート形式:** PNG, JPEG, JPG, WEBP

#### 2.1.5 画像サイズ検証
**WHEN** 受理した画像がサイズ上限を超えるとき、**THE SYSTEM SHALL** 生成処理を開始せずエラーメッセージを表示する。

**上限:** 10MB

#### 2.1.6 画像破損検証
**WHEN** 受理した画像が読み取り不能（破損等）なとき、**THE SYSTEM SHALL** 生成処理を開始せずエラーメッセージを表示する。

### 2.2 日報生成（フロントエンド）

#### 2.2.1 生成開始
**WHEN** ユーザーが「生成」操作を行ったとき、**THE SYSTEM SHALL** バックエンドへ画像を送信して生成を開始する。

#### 2.2.2 生成中の表示
**WHILE** 生成処理中、**THE SYSTEM SHALL** ローディング表示を行い、二重送信を抑止する。

#### 2.2.3 生成成功
**WHEN** 生成処理が成功したとき、**THE SYSTEM SHALL** 日報テンプレートに従うMarkdownを表示する。

**日報テンプレート（3セクション構成）:**
```markdown
## 作業内容
[生成された作業内容]

## 進捗状況
[生成された進捗状況]

## 課題・問題点
[生成された課題・問題点]
```

### 2.3 編集・コピー・エクスポート

#### 2.3.1 編集機能
**WHEN** 生成結果が表示されたとき、**THE SYSTEM SHALL** ユーザーがMarkdownテキストを編集できる。

#### 2.3.2 コピー機能
**WHEN** ユーザーが「コピー」操作を行ったとき、**THE SYSTEM SHALL** 編集後のMarkdownをクリップボードへコピーする。

#### 2.3.3 エクスポート機能
**WHEN** ユーザーが「エクスポート」操作を行ったとき、**THE SYSTEM SHALL** 編集後のMarkdownを`.md`ファイルとしてダウンロードさせる。

#### 2.3.4 エクスポートファイル名
**WHEN** エクスポートファイル名が未指定のとき、**THE SYSTEM SHALL** 一意性を確保できるデフォルト名を付与する。

**命名規則:** `daily-report-YYYYMMDD-HHmm.md`  
例: `daily-report-20260205-1430.md`

### 2.4 エラーハンドリング（フロントエンド）

#### 2.4.1 クライアントエラー（4xx）
**IF** バックエンドが4xxを返したとき、**THE SYSTEM SHALL** ユーザーに入力起因のエラーとして表示し再試行方法を提示する。

#### 2.4.2 サーバーエラー（5xx）
**IF** バックエンドが5xxを返したとき、**THE SYSTEM SHALL** ユーザーにシステム起因のエラーとして表示し再試行を促す。

#### 2.4.3 タイムアウトエラー
**IF** バックエンド通信がタイムアウトしたとき、**THE SYSTEM SHALL** タイムアウトとして表示し再試行を促す。

**タイムアウト設定:** 60秒

### 2.5 バックエンド API要件

#### 2.5.1 ヘルスチェック
**THE SYSTEM SHALL** GET `/healthz` エンドポイントを提供し、正常時に200を返す。

#### 2.5.2 画像受信
**WHEN** バックエンドが画像生成リクエストを受信したとき、**THE SYSTEM SHALL** 画像形式/サイズ/内容を検証する。

#### 2.5.3 画像前処理
**WHEN** 画像が検証に合格したとき、**THE SYSTEM SHALL** 必要に応じて前処理（リサイズ/圧縮）を行う。

**前処理ルール:**
- 最大解像度: 2048x2048
- 圧縮品質: JPEG 85%

#### 2.5.4 モデル呼び出し成功
**WHEN** モデル呼び出しに成功したとき、**THE SYSTEM SHALL** 3セクション構成のMarkdown日報を返す。

#### 2.5.5 モデル呼び出し失敗
**IF** モデル呼び出しに失敗したとき、**THE SYSTEM SHALL** 再試行可能なエラーとして扱い、適切なエラー応答を返す。

**リトライ設定:** 最大3回、指数バックオフ（1秒、2秒、4秒）

#### 2.5.6 CORS設定
**THE SYSTEM SHALL** 開発環境ではすべてのオリジンを許可し、本番環境では特定のオリジンのみを許可する。

#### 2.5.7 セキュリティ
**THE SYSTEM SHALL** 機密情報（APIキー、画像データの詳細）をログに出力しない。

## 3. 非機能要件

### 3.1 パフォーマンス
- 画像アップロード処理: 1秒以内にプレビュー表示
- 日報生成処理: 通常30秒以内、最大60秒（タイムアウト）
- UI応答性: すべてのボタン操作は100ms以内に反応

### 3.2 可用性
- 開発期間中は可用性要件なし
- 本番デプロイ後は99%以上を目標

### 3.3 セキュリティ
- Azure OpenAI APIキーは環境変数で管理
- 画像データは処理後即座に削除（一時保持のみ）
- HTTPS通信を使用（本番環境）

### 3.4 ユーザビリティ
- 1ページ完結のシンプルなUI
- 明確なエラーメッセージ
- ローディング状態の視覚的フィードバック

### 3.5 対応ブラウザ
- モダンブラウザ（Chrome, Firefox, Edge, Safari 最新版）
- IE11は非対応

### 3.6 データ管理
- データベース不使用
- 画像とMarkdownはセッション内のみで保持
- ブラウザリロード時にデータは消失（仕様）

## 4. 制約事項

### 4.1 技術的制約
- Azure OpenAI APIの使用量制限に準拠
- FastAPIの標準機能のみ使用（複雑なミドルウェア不使用）
- React 18以上を使用

### 4.2 スケジュール制約
- MVP完成まで2週間

### 4.3 リソース制約
- 開発者: フロントエンド1名、バックエンド1名
- 予算: Azure OpenAI API使用料のみ（開発・検証用）

## 5. 受け入れ基準（MVP完了条件）

### 5.1 基本フロー
✅ 画像1枚 → 生成 → 編集 → コピー → .md保存が一通り動作する

### 5.2 エラーハンドリング
✅ 非画像/サイズ超過/タイムアウト/モデル失敗で適切なエラー表示が出る

### 5.3 ヘルスチェック
✅ `/healthz` が 200 を返す

### 5.4 ドキュメント
✅ README.mdに起動方法、環境変数設定が記載されている
